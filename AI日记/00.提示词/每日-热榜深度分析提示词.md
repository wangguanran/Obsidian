# 每日-热榜深度分析提示词

你在执行“热榜抓取完成后的深度分析”任务。

## 任务目标

基于当天已经落地的热榜快照，生成一份**面向人类阅读**的深度分析稿，而不是机械分类汇总。

你必须做到两层：

1. **完整保留数据层**
   - 5 个来源都要保留
   - 每个来源都要完整列出 **至少 20 条**
   - 不允许只摘 3-5 条冒充完整榜单

2. **做好解释层 / 判断层**
   - 对最重要的实时新闻、争议话题、公共事件，按需补充搜索背景信息；优先少量高价值补充，不要为了显得全面而无节制外搜
   - 说明事情的前因后果、当前争议点、值得注意的信息
   - 写出你自己的分析和看法
   - 明确区分“事实”和“你的判断”

## 当前有效来源

1. 微博热搜（weibo-hot）
2. 知乎热榜（zhihu-hot）
3. GitHub Trending（github-trending）
4. AI 新闻热门（ai-news-hot）
5. AI 工具热门（ai-tools-hot）

## 输入文件

对于当天目录 `~/Obsidian/AI日记/00.素材/热榜/YYYY/MM/DD/`，至少读取：

- `manifest.md`
- `analysis.md`（本地脚本生成的基础分析）
- `weibo-hot.md`
- `zhihu-hot.md`
- `github-trending.md`
- `ai-news-hot.md`
- `ai-tools-hot.md`

## 输出文件

把深度分析稿写入当天目录下：

- `analysis-rich.md`

如果已存在，则覆盖为当天最新版本。

## 分析要求

### 一、完整榜单展示（硬要求）

在 `analysis-rich.md` 中，5 个来源都必须各自给出 **Top 20 完整列表**。

展示要求：
- 至少有：排名、标题、热度/指标（如果有）
- 可以附短摘要，但不能因为摘要太长而省略条目
- 如果某个来源实际只有不足 20 条，必须明确写出“当前只抓到 N 条”，不能装作满 20
- 对 **GitHub Trending** 与 **AI 新闻热门**，在完整榜单里尽量保留原始链接；至少在后文的完整解读部分必须保留链接

### 二、重点事件深挖（硬要求）

从下面这些来源里，挑选当天最值得解释的重点事件做深挖：
- 微博热搜
- 知乎热榜
- AI 新闻热门

优先选择：
- 突发新闻
- 高争议话题
- 需要背景知识才能理解的话题
- 容易被断章取义的话题

对每个重点事件，尽量补查：
- 事件是什么
- 前因后果是什么
- 当前的最新状态是什么
- 主要争议点是什么
- 哪些信息已经相对明确，哪些还不明确

如果是实时新闻，优先对 **1-3 个最值得补背景的重点事件** 使用 `web_search` + `web_fetch` 去补充外部来源；不是每个热点都强制外搜。若信息互相冲突，要明确说存在冲突，不要硬编结论。

### 三、写出你的看法（硬要求）

每个重点事件都要写“我的看法”或等价小节。

要求：
- 观点要建立在你刚核实过的信息上
- 可以有立场，但不要为了显得有立场而编造事实
- 可以指出媒体标题党、信息不完整、讨论偏移、情绪裹挟等问题
- 风格自然，像一个有判断力的人在讲，而不是公文汇报

### 四、GitHub Trending 的完整解读（新增硬要求）

除了在“各来源 Top 20 完整榜单”里保留 GitHub Trending Top 20 之外，还要额外给出一个**单独的 GitHub 热门完整解读**小节。

要求：
- 20 条尽量都覆盖，不要只挑 Top 5
- 每条至少包括：
  - 仓库名
  - 它是做什么的
  - 为什么今天值得看 / 你觉得它反映了什么方向
  - 指标（今日新增 stars / 总 stars / 语言，有就写）
  - 链接
- 写法不要只是复制 GitHub 原摘要，至少补一句人话解释
- 如果多个项目明显属于同一波（例如 agent harness、Claude Code 生态、OCR、语音等），要顺手点出共性

### 五、AI 新闻热门的完整解读（新增硬要求）

除了在“各来源 Top 20 完整榜单”里保留 AI 新闻热门 Top 20 之外，还要额外给出一个**单独的 AI 新闻热门完整解读**小节。

要求：
- 20 条尽量都覆盖，不要只挑 Top 5
- 每条至少包括：
  - 新闻标题
  - 来源
  - 这篇主要在讲什么
  - 值不值得看 / 你自己的简短判断
  - 链接（优先源站原文链接，只有拿不到时才使用 Google News 聚合链接）
- 不能只把标题翻译一下就结束；至少补一句说明它的主题、角度或含金量
- 如果当天存在明显的“重复稿 / 市场预测水稿 / 观点稿偏多”现象，要明确指出来

### 六、技术类来源的分析方式

#### GitHub Trending
不要只抄仓库名。要回答：
- 今天技术圈到底在热什么
- 这些项目共同反映了什么方向
- 哪些只是短期热度，哪些可能是真需求
- 你自己的判断是什么

#### AI 工具热门
要说明：
- 今天 Hugging Face 热门集中在哪些方向
- 是模型、数据集、还是 Space 更强
- 这代表了什么技术趋势
- 你对这些趋势的看法

## 推荐结构

你可以按这个结构写：

1. 标题与元信息
2. 今日总判断
3. 各来源 Top 20 完整榜单
4. GitHub 热门完整解读
5. AI 新闻热门完整解读
6. 今日重点事件深挖
7. 技术圈 / AI 圈趋势判断
8. 结尾总结

## 风格要求

- 中文
- 不要像日报公文
- 要有信息密度，也要有人味
- 可以明确说“我觉得”“我更倾向于”“我不太买账”
- 但要先把事实讲清楚，再给判断

## 禁止事项

- 不要编造热搜条目、排名、热度或背景事实
- 不要只做关键词归类就结束
- 不要把 20 条榜单缩成 3-5 条
- 不要把未经核实的实时新闻说成既成事实
- 不要把观点写得像空泛鸡汤

## 完成标准

完成后，最终输出给调用方的摘要应该是 1 行，包含：
- 日期
- 输出文件路径
- 是否所有来源都达到 20 条
- 你挑了几个重点事件做深挖
