# 分析：NVP6188 四路热插拔通道解锁隔离与保帧修复

**版本号：v1.0**
**对应文档：** nvp6188四路热插拔修复

## 技术背景

NVP6188 是 Nextchip 的 4 路 AHD/CVBS 模拟视频解码芯片，输出 MIPI CSI-2 YUV（多虚拟通道）给 SoC。在 CamX 框架中：

- **IFE（Image Front End）**：RDI（Raw Dump Interface）直通路径处理 YUV sensor 数据，`IFEOutputPortRDI0~3` 对应 4 个虚拟通道；
- **memcpy 节点**：CHI-CDK OEM 节点，负责格式转换（UYVY→NV12）与数据搬运，位于传感器处理链路末端；
- 热插拔场景下，模拟视频线拔/插会让解码器输出 vloss（信号丢失）/VFC（格式变化）事件，CamX 侧需据此做通道级状态管理。

## 代码改动分析

### camxnvp6188detect.cpp/.h（核心状态机）

原实现的问题在于把 4 通道当作一个整体管理。重构后：

- **每通道独立状态**：`pendCnt / unlocked / unlockStreak / cablePresentStreak / relockStreak / relockHoldUntilMs / plugNudgeCount / plugKickCount / a8WasLost` 全部 per-CH 数组化，解锁流程只对 rising-edge 丢失的通道生效 → sibling isolation；
- **relockHoldUntilMs**：重锁成功后的一段绝对时间窗口内，VFC 闪烁不再触发解锁判定（`a8WasLost` 用于识别真正的 rising-edge，而非窗口内抖动）；
- **cablePresentStreak**：连续 N 轮 `!vloss` 才确认插回，抗线缆接触抖动；
- **plugNudgeCount / plugKickCount**：对 set_chn 与 bank13 寄存器写入做限频（cap），避免反复拔插时寄存器 epoch 状态漂移；
- **primarySticky**：最近丢失的主通道 sticky，重锁流程优先处理。

### camxifenode.cpp/.h（帧级联动）

- `ProcessingNodeFenceCallback()` 挂到 RDI0~3 的 fence 回调：从 `m_pSensorCaps->pSensorName` 解析芯片（`Nvp6188ChipFromSensorName`），按 `portId - IFEOutputPortRDI0` 得到 vc 号，`Nvp6188NoteRdiFence()` 上报 requestId → 拔插状态机与真实出帧同步，避免异步检测线程与帧流脱节。

### camxchinodememcpy.cpp/.h（hold-last）

- 新增 NV12 帧缓存（Y/UV 双平面 + 尺寸/stride 记录），直播模式照常转换；
- `signalLocked=0` 时输出纯蓝（solid blue），不冻结、不等待 MIPI（防止流水线挂起），同时保持最后一帧（hold-last）便于事后取证；
- 析构释放缓存，防泄漏。

## 潜在风险

1. **状态机复杂度上升**：per-CH 字段多（9 个数组 + 主通道 sticky），后续维护需注意初始化与复位路径（`reset` 时全部清零）；
2. **hold-off 窗口时长**：`relockHoldUntilMs` 过长会掩盖真实拔线（新一次拔线在窗口内不被识别），过短则抖动抑制失效——需按实际 VFC 抖动时长标定；
3. **memcpy 蓝屏策略**：lock=0 输出蓝屏是产品策略，若客户需要黑屏/测试图需再调整；
4. **RDI fence 回调开销**：每个 RDI port 的 fence 回调增加一次 sensor 名解析与函数调用，高帧率下需确认无性能回退。

## 回归测试建议

- 4 路 1080p@30 直播稳定性（≥24h）；
- 热插拔：单路/多路/全路拔插循环 ≥100 轮，观察日志中解锁/重锁/插回状态机是否收敛；
- 拔线后恢复：等待 10s 再插回（验证 relock hold-off 过期后能识别新拔线）；
- memcpy 节点内存：反复拔插后 RSS 不增长（验证缓存释放）；
- 与其他 CamX 场景（拍照/录像/多摄）回归，确认 IFENode 回调不干扰正常流。

## 与现有驱动架构的关系

- 该修复全部位于 CamX 框架层（vendor 侧），不涉及内核驱动与 DT，属于 OEM 定制逻辑（NVP6188 detect 模块本身即 OEM 扩展）；
- 与平台其他 CamX 问题案例（如 Camera GPIO 释放）互不依赖；若后续在 134 建立 SRM955 源码树，可补拉 6 个文件归档。
