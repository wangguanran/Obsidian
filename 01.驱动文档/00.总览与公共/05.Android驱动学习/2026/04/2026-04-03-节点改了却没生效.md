## 节点改了却没生效

### 今日主题
用你库里的 **SM6225 多版本 DTS/DTBO 分流案例**，走一遍很典型的现场：**节点明明改了，编译也过了，驱动现象却还是老样子。**

### 为什么今天学这个
这类问题最容易把人拖进无效加班：
- 你会怀疑驱动 `probe()` 没走对
- 会怀疑 regulator / gpio 没申请到
- 甚至开始改驱动里的 if-else

但这个案例真正要你记住的是：**有时不是驱动没吃到资源，而是系统启动时就没选中你改的那份 overlay。**

### 核心概念
#### 1. DTS 改了，不等于运行时真的生效
在 SM6225 这个案例里，版本差异不是靠驱动里判断，而是靠 **bootloader + board-id + stage + DTBO best-fit** 先决定系统到底加载哪份 overlay。

所以现场要先问一句：
**现在机器跑起来时，吃到的到底是不是你刚改的那份 dtbo？**

#### 2. “现象像驱动问题”，根因可能在匹配层
如果 overlay 没命中，会出现很迷惑的表象：
- 节点源码里已经有 `regulator-fixed`
- `pinctrl-0`、GPIO、功能节点也都写了
- 但运行时外设还是像没上电、没切脚、没绑定对资源

这不是驱动装傻，是 **版本资源从一开始就喂错了**。

#### 3. 多版本机型最怕“以为自己改到了目标版本”
你现有文档里，SM6225 的做法很清楚：
- bootloader 把 `stage` 注入 `board-id minor`
- DT 匹配阶段按 `BoardIdForMatch` 选 overlay
- 版本差异放进 `khaje-idp-v101-overlay.dts` / `khaje-idp-v102-overlay.dts`
- 驱动只消费分流后的标准资源

这套设计的重点不是“写得优雅”，而是防止 **不同硬件版本互相串配置**。

### 关键路径 / 关键文件
今天只盯这几个入口就够了：
- `LocateDeviceTree.c`：看 `stage` 有没有被写进匹配用的 `board-id`
- `qcom/Makefile`：确认目标版本 overlay 是否真的参与构建
- `khaje-idp-pm7250b.dtsi`：只留公共层，别残留版本差异节点
- `khaje-idp-v101-overlay.dts` / `khaje-idp-v102-overlay.dts`：确认差异资源到底放在哪个版本里
- 运行时目标：核对外设最终拿到的 `regulator / pinctrl / gpio`

### 常用命令 / 日志点
现场建议先回答“命中了谁”，再回答“资源对不对”：

```bash
dmesg | grep -i "dtb\|dtbo\|board\|stage\|overlay"
dmesg | grep -i "probe\|defer\|gpio\|pinctrl\|regulator"
cat /proc/device-tree/model 2>/dev/null
find /proc/device-tree -iname "*board*" 2>/dev/null | head
```

如果内核日志抓不到太多信息，就回到文档和构建产物：
1. 目标 overlay 是否真的被编进镜像
2. `board-id minor` 是否和 stage 规划一致
3. base dtsi 是否还残留版本差异配置

### 真实问题场景
这次案例里，`se5v` 供电、buzzer/NFC 相关资源被拆进不同版本 overlay。

如果你只改了某个 dtsi，或者 overlay 版本没命中，就会看到这种反直觉现象：
- 代码里明明有 `se5v`
- 节点也明明配了 `amp-supply` / `vdd-supply`
- 但运行时外设仍然像没拿到正确供电

这时候继续盯驱动 `probe()` 往往是绕远路。真正该查的是：
1. 机器当前 stage 是多少
2. 它最终匹配到了 v101 还是 v102
3. 你修改的那份资源，是否就在被命中的 overlay 里

### 和当前项目的联系
这个案例对你现有知识库很有代表性，因为你最近几张卡片已经反复提到：
- `读 ID 失败` 不一定是通信本身，可能是资源没喂对
- `probe defer` 常常不是驱动坏，而是依赖没齐
- Qualcomm/SM6225 这类平台还要再多看一层：**overlay 有没有命中目标版本**

也就是说，今后遇到 “节点写了、驱动也像对、现象却不对” 的场景，排查顺序应该改成：
**先证实运行时配置命中，再谈驱动逻辑。**

### 一句话总结
**DTS 改了却没生效，先别急着怪驱动；在多版本平台上，先确认系统启动时到底选中了哪份 overlay。**
