## 总线与日志速查卡

### 今日主题
把 Android 驱动现场最常翻的几类入口收成一页：**I2C / platform / 运行时 DT / deferred probe / 关键日志**。

### 为什么今天学这个
前几天已经把主线讲清了：
- 先分 **match / probe / 资源 / 通信 / 上层**
- DTS 不只是写 `compatible`
- PN7221 这类案例要看完整时间线

那今天就收口成一张速查卡。现场真出问题时，最怕的不是不会，而是脑子里口子太多、顺序乱掉。

### 核心概念
#### 1. 先记住一句总口诀
**先确认“设备在不在”，再确认“驱动绑没绑”，再确认“资源齐不齐”，最后才看“寄存器和业务逻辑”。**

#### 2. 几类总线怎么理解
- **platform**：多半是 SoC 内建控制器或板级虚拟设备，核心看 `compatible`、platform device、资源申请。
- **I2C**：最常见于 TP、Sensor、Charger、NFC，小芯片 bringup 基本都绕不开它。
- **SPI**：逻辑和 I2C 类似，但更常多看 CS、mode、时钟、半双工/全双工。

别被总线名字吓到。**入口不同，主线还是 match → probe → init。**

### 关键路径 / 关键文件
- 驱动入口：`of_match_table`、`probe()`、`remove()`
- 运行时 DT：`/proc/device-tree/...`
- I2C 设备与驱动：`/sys/bus/i2c/devices`、`/sys/bus/i2c/drivers`
- platform 设备与驱动：`/sys/bus/platform/devices`、`/sys/bus/platform/drivers`
- SPI 设备与驱动：`/sys/bus/spi/devices`、`/sys/bus/spi/drivers`
- defer 观察口：`/sys/kernel/debug/devices_deferred`

### 常用命令 / 日志点
```bash
dmesg | grep -i "probe\|defer\|fail\|gpio\|irq\|regulator\|clk\|i2c\|spi"
logcat -b all | grep -i "abort\|timeout\|hal"
ls /sys/bus/i2c/devices && ls /sys/bus/i2c/drivers
ls /sys/bus/platform/devices && ls /sys/bus/platform/drivers
ls /sys/bus/spi/devices && ls /sys/bus/spi/drivers
cat /sys/kernel/debug/devices_deferred
cat /proc/device-tree/.../compatible
cat /proc/device-tree/.../status
```

现场不用一口气全跑。优先顺序建议是：
1. `dmesg`
2. 对应 `/sys/bus/*`
3. `devices_deferred`
4. 运行时 `device-tree`

### 真实问题场景
#### 场景 1：TP / Sensor 完全不进 probe
先查这 5 件事：
1. 节点挂没挂对 I2C 控制器
2. `status` 是否真是 `okay`
3. `compatible` 是否对上驱动 `of_match_table`
4. `/sys/bus/i2c/devices` 里有没有实例
5. 是否其实卡在 `devices_deferred`

#### 场景 2：probe 进了，但读 ID 失败
别急着改寄存器表，先看：
- reset / irq GPIO 极性对不对
- pinctrl 是否真切到工作态
- regulator / clk 有没有成功申请
- I2C 地址、速率、时序是否和板级连接一致

#### 场景 3：上层只看到 HAL timeout / abort
像你库里的 **PN7221**，上层崩不代表根因在上层。要把：
- kernel 的 I2C 异常
- HAL 的 `write_unlocked failed` / `ret(-107)`
- framework 的 timeout / abort
串成同一时间线看。

### 和当前项目的联系
- **PN7221**：最适合练“日志三层联看”，尤其是 I2C 异常如何一路传到 HAL / Framework。
- **SM6225 overlay 笔记**：提醒你“源码改了”不等于“运行时 DT 生效了”，先确认最终 dtbo 命中。
- **TP / Sensor / Charger**：虽然很多页面还在总览阶段，但 bringup 第一轮检查项已经可以统一成这张卡：**总线实例、驱动绑定、资源依赖、通信读写**。
- **DA265 / QMA6100P 这类加速度计资料**：源码索引里已经能看到典型 `i2c_probe()`、`i2c_check_functionality()`、chip id 读取路径，后面做单模块专题时可以直接拿来拆。

### 一句话总结
**现场排驱动，先别扑进代码海里；先用总线、sysfs、运行时 DT、deferred probe 和日志，把问题缩到“没枚举 / 没绑定 / 缺资源 / 通信失败”这四类里。**
