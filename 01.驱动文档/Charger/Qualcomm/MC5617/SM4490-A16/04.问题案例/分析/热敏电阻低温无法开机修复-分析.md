# 分析：MC5617 热敏电阻低温无法开机修复

**版本号：v1.0**
**对应文档：** 热敏电阻低温无法开机修复.md

## 技术背景

**JEITA 温度保护**：日本 JEITA 标准要求充电器在电池温度过低/过高时限制或禁止充电。Qualcomm SCHG 充电器通过 `SCHG_CHGR JEITA_EN_CFG (0x1090)` 寄存器使能 JEITA 的 AFP（Automatic Feature Protection）COLD/HOT 保护。

**问题链条**：
- -15°C（热敏电阻 846.6kΩ）时 JEITA 低温保护触发 → AFP_COLD 硬件保护 → 充电 hard-limit → 充电相关电源/状态异常 → 样机无法开机。

**双层配置点**：
1. **XBL/PSI 阶段**（pm_config_target_sbl_sequence.h）：SBL 阶段按 PSI 序列表配置 PMIC，此阶段若 JEITA 使能且温度超限，AFP 可能在启动早期触发；
2. **BattMan 阶段**（pm_peripheral_chgr.c）：ADSP 上的电池管理进程，通过 API 配置 JEITA 位。

## 代码改动分析

### pm_peripheral_chgr.c（+12 行）

```c
#if defined(ODM_PROJECT_MC5617)
    enable = FALSE;
    (void)jeita_cfg_type;
    status = PM_OUT(..., SCHG_CHGR_JEITA_EN_CFG, 0x00);   // 整寄存器清 0
#else
    status = PM_OUT_MASK(..., (1 << jeita_cfg_type), ...); // 按位掩码
#endif
```

- 原实现 `PM_OUT_MASK` 按 `jeita_cfg_type` 位掩码写入：其他调用方后续 enable AFP_COLD/HOT 时，会把对应 bit 置位 → JEITA 残留 → 触发 AFP
- MC5617 分支直接整寄存器写 0x00：无论调用方传什么参数，JEITA_EN 恒为 0，彻底规避

### pm_config_target_sbl_sequence.h（#196564 +4/-1）

- 引入 `odm_features.h`（平台宏定义）
- PSI LUT 追加 `PM_SBL_WRITE 0x1090 0x00 0xFF` 表项：SBL 阶段直接写 0
- 注释特别说明：**宏内不能用 #if**（PSI 表是宏展开结构，条件编译会破坏表结构），所以用平台无关的固定表项 + odm_features.h 控制整体编译

## 潜在风险

1. **全平台影响**：PSI 表项无 #if 保护，若该表项在其它机型生效，会关掉所有机型的 JEITA 低温/高温保护 → 必须确认该 PSI 表仅 MC5617 的 clarence target 使用（已用 `pm_config_target_sbl_sequence.h` 按 target 隔离）
2. **电池安全**：JEITA 全关后低温充电失去硬件保护 → 需评估是否仅影响 XBL 阶段（此时电池管理由软件控制），长期可靠性需热测试
3. **位掩码语义变化**：`(void)jeita_cfg_type` 忽略参数，若上层依赖返回值区分配置结果，行为改变

## 回归测试建议

- -15°C / 0°C / 25°C / 45°C / 60°C 温度点开机 + 充电循环
- 高温（AFP_HOT）场景确认仍受控（若 JEITA 已关，需验证其它保护机制）
- 正常温度快速充电功能对比

## 与现有驱动架构的关系

- 充电管理跨 XBL（PSI）+ ADSP（BattMan）+ HLOS（smblib）三层，本用例是 XBL/BattMan 两层协同修改
- clarence 为 PMIC target 代号（对应具体 PMIC 型号），PSI 表按 target 独立
- `ODM_PROJECT_MC5617` 平台宏与其它项目（A16 等）在 odm_features.h 中统一管理
