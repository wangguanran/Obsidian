## 现象

热敏电阻阻值 846.6kΩ（对应 -15°C）时，[项目代号] 样机**无法正常开机**（cannot be powered on normally）。

## 环境

| 项 | 值 |
|----|-----|
| 机型 | [项目代号] |
| 温度 | -15°C（热敏电阻 846.6kΩ） |
| PMIC | PM855B / SMB2351（SCHG 充电器） |
| 影响层 | XBL（SBL PSI 序列）+ BattMan（ADSP） |

## 关键日志

（开机阶段无明显错误日志——问题表现为启动阻断，根因为 JEITA/AFP 保护）

## 根因分析

JEITA 温度保护（AFP_COLD/HOT）在低温下触发后，充电器会进入 hard-limit 状态阻断充电；而该平台启动流程依赖充电相关配置，JEITA 保护使能位残留时：

1. **XBL 阶段**：PMIC PSI 序列（pm_config_target_sbl_sequence.h）未显式关闭 `SCHG_CHGR JEITA_EN_CFG (0x1090)`，JEITA 默认使能 → SBL 阶段 AFP 保护可能触发；
2. **BattMan 阶段**：`pm_peripheral_chgr.c` 的 JEITA 配置接口使用 `PM_OUT_MASK` 按位掩码写入，其他调用方（BattMan 后续 enable AFP_COLD/HOT）设置后，JEITA bit 仍可能残留 → 触发 HW AFP / hard-limit → 阻断冷启动。

## 处理方案

在 XBL 与 BattMan 两层都强制关闭 JEITA（0x1090 = 0x00）：

1. **XBL（#196516 / #196564 的 pm_config_target_sbl_sequence.h）**：
   - 引入 `odm_features.h`
   - PSI Sequence LUT 中追加表项：`PM_SBL_WRITE, 8, 0x1090, 0x00, 0xFF`（整寄存器写 0，注释说明宏内不能用 #if）
2. **BattMan（pm_peripheral_chgr.c）**：
   - `#if defined(ODM_PROJECT_[项目代号])` 分支：`enable=FALSE`，忽略 jeita_cfg_type，直接 `PM_OUT(..., SCHG_CHGR_JEITA_EN_CFG, 0x00)` 整寄存器清零（不走位掩码），保证任何调用方都不会残留 JEITA bit
   - 其他平台保持原 `PM_OUT_MASK` 逻辑

## 配置方式

### 平台宏

- 代码级配置：`#if defined(ODM_PROJECT_[项目代号])`（在 odm_features.h 中定义）
- 编译时按项目定义 ODM_PROJECT_[项目代号] 即可生效，其他平台不受影响

### PSI 序列表项（pm_config_target_sbl_sequence.h）

```c
/* [项目代号]: disable JEITA AFP (SCHG_CHGR JEITA_EN_CFG @ 0x1090). Do not use #if inside this macro. */
{    0,   0,   PM_SBL_WRITE,     8,    0x1090,    0x00,   0xFF,    0,       0 },
```
