## 现象

JD9365DA 720p 屏显示错误（花屏/初始化异常）。AP 侧与 BP 侧（UEFI）的 DSI init data 均不正确：

- AP 侧：dsi-panel-jd9365da-video.dtsi 中 init 命令以 0x15（短写）发送，DCS 参数被误判为命令导致初始化序列错误；bengal-sde-display-idp.dtsi 中同时包含 ST7701S/JD9365 两套 panel 与错误的电源配置，且引用了被删除的 pinctrl 文件；
- BP 侧：Panel_jd9365da_720p_vid.xml 中多个寄存器写指令类型错误（0x05 应为 0x15），部分寄存器值错误（如 0x29 应为 0x41），复位释放等待 `FF c8` 大小写不一致导致解析问题。

## 环境

- 平台：SM6115-A14（[项目代号] 项目）
- AP 仓库：LA.VENDOR.13.2.1（分支 [项目代号]），vendor/qcom/proprietary/display-devicetree/
- BP 仓库：iot-high-mid-2024-spf-1-0_amss_standard_oem（分支 master_meig），BOOT.XF.4.1/
- 屏：JD9365DA 720p video 模式

## 根因分析

1. **init data 指令类型（AP/BP 双侧）**：
   - DSI 命令头 `29` = generic long write（长写，带校验和），`15` = short write 2 参数（短写，无校验和），`05` = short write 0 参数。
   - JD9365DA 寄存器设置需要以 long write（29）发送，原 AP 侧全部使用 `15 01`（短写），BP 侧部分使用 `05`（0 参数短写），导致寄存器值与地址被当作命令/参数解析错误 → 显示异常。
   - #196371 将 AP 侧全部 `15 01` 改为 `29 01`（E0~E3/80 页切换及全部寄存器设置）；#196374 将 BP 侧 `05 10/11/28/29/35 00` 改为 `15 xx xx` 正确短写，并修正寄存器值（0x28:00→5F、0x29:00→41、0x35:00→5F）。
2. **AP 侧 DT 电源与面板配置混乱**：bengal-sde-display-idp.dtsi 是 Bengal 参考版，被 [项目代号] 带入 ST7701S/JD9365 panel 后与 scuba-sde-display-idp.dtsi 重复定义电源，且 bengal-sde-display-pinctrl.dtsi 在父提交中被删除（29 行）而 bengal-sde-display-idp.dtsi 顶部仍 include 它 → 编译中断。修正方案：bengal-sde-display-idp.dtsi 回归纯 Bengal 参考形态（仅 td4330 面板），删除 pinctrl include 与 panel include、[项目代号] LCM power rails 全部移除（电源配置保留在 scuba 侧），sde_dsi default panel 改回 td4330。
3. **UEFI 构建破坏**：上一轮 bring up（#166f877589）在 MDPPlatformLib.c 中无条件声明 `EFI_QCOM_PMIC_GPIO_PROTOCOL *PmicGpioProtocol` 且未在非 [项目代号] 分支使用，导致其他 UEFI 构建报 unused 错误；Core.fdf 缩进错误导致 `FILE FREEFORM` 解析异常。#196216 将声明移入 `#if defined(ODM_PROJECT_[项目代号])`，并修正 Core.fdf 缩进。

## 处理方案

### AP 侧（#196371，+218/-379）

1. **bengal-sde-display-idp.dtsi（+2/-132）**：
   - 删除 `#include "bengal-sde-display-pinctrl.dtsi"`（该文件已删）及 `dsi-panel-[项目代号]-st7701s-boe397-video.dtsi`、`dsi-panel-jd9365da-video.dtsi` include；
   - 重写 [项目代号] LCM power rails（display_panel_vddio/avdd/avee、dsi_panel_pwr_supply_[项目代号] 及两个 panel 的 supply 绑定）全部移除——电源配置保留在 scuba-sde-display-idp.dtsi：
     - GPIO111 LCD_IOVCC_EN → IOVDD 1.8V（vddio）
     - GPIO112 LCM_VDD2V8_EN → VCC 2.8V（avdd）
     - GPIO105 DISP_BIAS_EN（avee）
     - GPIO82 LCD_RST_N、GPIO81 LCM_TE、GPIO24 BL_FB、PM4125 GPIO2 BL_PWM
   - sde_dsi 默认面板改回 `&dsi_td4330_truly_v2_video`；synaptics panel 列表移除 ST7701S/JD9365。
2. **bengal-sde-display-pinctrl.dtsi（DELETED，-29）**：删除文件（父提交版本 437B，已归档并注明已删除）。
3. **dsi-panel-jd9365da-video.dtsi（+207/-207 全量重写 init）**：on-command 中所有 `15 01` → `29 01`（long write），寄存器序列与参数保持不变。
4. **scuba-sde-display-idp.dtsi（+0/-9）**：删除 `&dsi_st7701s_boe397_video`/`&dsi_jd9365da_video` 中重复的 vddio/avdd/avee supply 引用及注释（电源在 scuba 侧由 dsi_panel_pwr_supply_[项目代号] 统一提供）。
5. **scuba-sde-display.dtsi（+0/-2）**：删除 splash_region 节点上多余的 ABL EBS 注释（节点本身保留）。

### BP 侧（#196374，+6/-6）

**Panel_jd9365da_720p_vid.xml**（UEFI init data +15/-6 实际 diff 6 处）：
- `05 10 00` → `15 10 5F`、`05 11 00` → `15 11 5F`、`05 28 00` → `15 28 5F`、`05 29 00` → `15 29 41`、`05 35 00` → `15 35 5F`（命令类型 05→15 并修正寄存器值）；
- 终止序列 `FF c8` → `FF C8`（大小写统一，避免命令解析差异）。

### UEFI 修复（#196216，+14/-3）

- **Core.fdf**：`FILE FREEFORM` 缩进修正（+1/-1）；
- **MDPPlatformLib.c**：`EFI_QCOM_PMIC_GPIO_PROTOCOL *PmicGpioProtocol` 声明从函数顶部移入 `#if defined(ODM_PROJECT_[项目代号])` 块（+2/-1），未用变量不再破坏其他 UEFI 构建；
- **MDPPlatformLibPanelCommon.c**：删除函数顶部未使用的 `PmicGpioProtocol` 声明（+2/-2），[项目代号] 分支内保留。

## 配置方式

### 1. AP 侧电源（scuba-sde-display-idp.dtsi，[项目代号] LCM power rails）

```dts
&soc {
    display_panel_vddio: display_panel_vddio {
        compatible = "regulator-fixed";
        regulator-name = "display_panel_vddio";
        regulator-min-microvolt = <1800000>;   /* GPIO111 LCD_IOVCC_EN → IOVDD 1.8V */
        regulator-max-microvolt = <1800000>;
        gpio = <&tlmm 111 0>;
        enable-active-high;
        startup-delay-us = <10000>;
    };
    display_panel_avdd: display_panel_avdd {
        compatible = "regulator-fixed";
        regulator-name = "display_panel_avdd";
        regulator-min-microvolt = <2800000>;   /* GPIO112 LCM_VDD2V8_EN → VCC 2.8V */
        regulator-max-microvolt = <2800000>;
        gpio = <&tlmm 112 0>;
        enable-active-high;
        startup-delay-us = <10000>;
    };
    display_panel_avee: display_panel_avee {
        compatible = "regulator-fixed";
        regulator-name = "display_panel_avee";
        regulator-min-microvolt = <2800000>;   /* GPIO105 DISP_BIAS_EN */
        regulator-max-microvolt = <2800000>;
        gpio = <&tlmm 105 0>;
        enable-active-high;
        startup-delay-us = <10000>;
    };
};
```

LCD 复位 GPIO82 LCD_RST_N、TE GPIO81 LCM_TE、背光 GPIO24 BL_FB（4inch LOW/40mA，5inch HIGH/80mA，由 BP 设置）、PWM PM4125 GPIO2 BL_PWM。

### 2. BP 侧 UEFI panel init（Panel_jd9365da_720p_vid.xml）

```xml
<!-- 页 1 寄存器设置使用 long/short write 类型 29/15，值 5F 系 -->
15 10 5F
15 11 5F
...
15 28 5F
15 29 41
...
15 35 5F
<!-- 结束序列 -->
FF C8
```

### 3. UEFI 构建开关

```c
/* MDPPlatformLib.c: PmicGpioProtocol 仅 [项目代号] 定义 */
#if defined(ODM_PROJECT_[项目代号])
  EFI_QCOM_PMIC_GPIO_PROTOCOL *PmicGpioProtocol = NULL;
#endif
```

## 验证方式

1. UEFI（BP）阶段：开机 logo/早期 splash 正常显示，无花屏（init data 修正后）。
2. Kernel（AP）阶段：`dmesg | grep -i "mdss\|dsi"` 无 init 错误，进入系统后 720p 正常显示，TE/背光正常。
3. 编译验证：三个补丁均通过 134 源码树父提交重建（✅ 可干净应用）；UEFI 其他项目构建不受 PmicGpioProtocol 影响。

## 结论

JD9365DA 显示错误的根因是 AP/BP 两侧 DSI init data 命令类型与寄存器值错误，以及 AP 侧 DT 残留的 Bengal 参考配置。通过 #196371（AP）/ #196374（BP）分别修正 init data，并用 #196216 修复 UEFI 构建问题，显示正常。三个 Change 同属 Task 118727，联合归档。
