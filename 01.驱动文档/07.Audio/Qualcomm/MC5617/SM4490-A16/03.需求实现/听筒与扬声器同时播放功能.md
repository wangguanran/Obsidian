## 需求描述

MC5617 平台需要支持**扬声器（Speaker）与听筒（Handset）同时播放**的功能。该能力常见于免提/大音量场景：媒体音频同时从外放喇叭和听筒（接收器）输出，提升播放响度与覆盖范围，例如免提通话外放增强、车载/工业平板大音量播放等场景。

需求要点：

- 媒体类播放（Media Playback）时，音频同时输出到 Speaker 和 Handset 两条通路；
- **不适用于** VOIP / 电话（Telephony）等语音通路，避免回声/啸叫风险；
- 默认**关闭**，通过属性开关控制，便于量产按项目需求开启。

## 方案

采用 **HAL 层配置允许多路输出** 的方案（补丁注释中的 Option A）：

1. **APM（Audio Policy Manager）仍只选择 SPEAKER**，音频 HAL 在向 PAL（Primitive Audio Library）下发设备列表之前，通过 `Platform::customizePalDevices()` 钩子检查属性开关；
2. 当开关开启且当前 usecase 为媒体播放、设备列表恰好只有 SPEAKER 时，**复制一份设备并把 id 改为 HANDSET，追加到设备列表**，使同一路媒体流同时送往 Speaker 与 Handset 两条 MI2S backend；
3. 双通路开关通过 product 属性 `persist.vendor.audio.media.spk_rcv_dual` 控制（parrot.mk 中默认置 `false`，代码中同时兼容 `vendor.audio.media.spk_rcv_dual` 非 persist 写法）。

### 关键实现细节（Platform.cpp）

```cpp
namespace {

constexpr const char* kMediaSpkRcvDualProp = "vendor.audio.media.spk_rcv_dual";

// 仅媒体播放类 usecase 生效（不包含 VOIP/telephony）
bool isMediaPlaybackUsecaseForSpkRcvDual(const Usecase tag) {
    switch (tag) {
        case Usecase::PRIMARY_PLAYBACK:
        case Usecase::LOW_LATENCY_PLAYBACK:
        case Usecase::DEEP_BUFFER_PLAYBACK:
        case Usecase::ULL_PLAYBACK:
        case Usecase::MMAP_PLAYBACK:
        case Usecase::COMPRESS_OFFLOAD_PLAYBACK:
        case Usecase::PCM_OFFLOAD_PLAYBACK:
        case Usecase::SPATIAL_PLAYBACK:
            return true;
        default:
            return false;
    }
}

void maybeAppendHandsetForMediaSpkRcvDual(const Usecase tag,
                                          std::vector<pal_device>& palDevices) {
    const bool dualEnabled =
            ::android::base::GetBoolProperty(kMediaSpkRcvDualProp, false) ||
            ::android::base::GetBoolProperty("persist.vendor.audio.media.spk_rcv_dual", false);
    if (!dualEnabled) return;
    if (!isMediaPlaybackUsecaseForSpkRcvDual(tag)) return;
    if (palDevices.size() != 1 || palDevices[0].id != PAL_DEVICE_OUT_SPEAKER) return;

    pal_device handset = palDevices[0];
    handset.id = PAL_DEVICE_OUT_HANDSET;
    handset.custom_config.custom_key[0] = '\0';
    palDevices.push_back(handset);
    LOG(INFO) << __func__ << ": media dual path SPEAKER+HANDSET (" << kMediaSpkRcvDualProp
              << "=1)";
}

}  // namespace

void Platform::customizePalDevices(...) const noexcept {
    ...
    maybeAppendHandsetForMediaSpkRcvDual(tag, palDevices);
}
```

逻辑说明：

- **双属性兼容**：同时检查 `vendor.audio.media.spk_rcv_dual` 与 `persist.vendor.audio.media.spk_rcv_dual`，任一为 true 即开启；
- **usecase 白名单**：PRIMARY / LOW_LATENCY / DEEP_BUFFER / ULL / MMAP / COMPRESS_OFFLOAD / PCM_OFFLOAD / SPATIAL 播放均适用，VOIP、telephony 等语音通路不受影响；
- **设备条件**：仅当设备列表恰为单个 SPEAKER 时追加 HANDSET，避免与耳机、蓝牙等其他输出设备叠加；
- 追加的 HANDSET 设备复制自原 SPEAKER 设备（采样率、位宽等配置一致），并清空 custom_key。

## 配置方式

双通路功能默认关闭，通过属性控制：

```bash
# 查看当前状态（默认 false）
getprop persist.vendor.audio.media.spk_rcv_dual

# 开启：扬声器 + 听筒同时播放
setprop persist.vendor.audio.media.spk_rcv_dual true

# 关闭
setprop persist.vendor.audio.media.spk_rcv_dual false
```

量产默认值在 `parrot.mk` 中定义（可改为 `true` 后随系统镜像固化）：

```makefile
#Simultaneous audio output
PRODUCT_PROPERTY_OVERRIDES += \
persist.vendor.audio.media.spk_rcv_dual=false
```

> 注意：属性生效需重启 audio HAL 或重启系统；`persist.` 前缀属性在重启后保留。

### 1. 属性验证

```bash
adb shell getprop persist.vendor.audio.media.spk_rcv_dual
# 预期：true（开启后）
```

### 2. 音频路径功能测试（核心验证）

```bash
# 开启双通路
adb shell setprop persist.vendor.audio.media.spk_rcv_dual true
adb shell stop && adb shell start   # 或重启，使 HAL 重新加载属性

# 播放测试音频，同时输出到 speaker 和 handset
adb push test.wav /data/local/tmp/
adb shell tinyplay /data/local/tmp/test.wav
# 预期：扬声器与听筒同时发声，音量相当，无异常/失真
```

### 3. 日志验证

```bash
adb logcat -d | grep -i "spk_rcv_dual"
# 预期：HAL 打印 "media dual path SPEAKER+HANDSET (vendor.audio.media.spk_rcv_dual=1)"
```

### 4. 回归验证（不适用场景）

- 关闭属性后播放：仅扬声器出声；
- 通话/VOIP 场景：即使属性开启，也不应出现听筒+扬声器同播；
- 插耳机/蓝牙播放：不受影响，仍只走对应设备。

## 结论

通过 audio HAL `customizePalDevices()` 钩子在设备列表下发前追加 HANDSET 设备，以最小的改动（仅 HAL 层，不动 APM/内核）实现了媒体流 Speaker+Handset 双通路同时播放。功能默认关闭、按属性开启，且只作用于媒体播放 usecase，不影响语音通路，方案安全可回退。
