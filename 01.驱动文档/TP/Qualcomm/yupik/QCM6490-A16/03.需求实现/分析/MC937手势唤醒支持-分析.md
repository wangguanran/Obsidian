# 分析：MC937 手势唤醒支持

**版本号：v1.0**
**对应文档：** MC937手势唤醒支持.md

## 技术背景

**手势唤醒（Gesture Wakeup）**：息屏状态下，触摸屏检测特定手势（双击、滑动等）并唤醒系统。实现需要两条链路配合：

1. **显示链路**：屏灭时显示驱动必须保持通知触摸驱动（DRM panel event notifier），同时保持触摸 IC 的中断唤醒能力（irq_wake），否则系统 suspend 后中断被关闭；
2. **触摸链路**：触摸驱动在手势模式下不关闭中断，捕获手势事件后通过 `input_report_key(KEY_WAKEUP)` 上报唤醒。

yupik (QCM6490) A16 平台显示使用 msm/dp（DP/eDP），触摸使用 eGalax / SiS 双方案。

## 代码改动分析

### 显示侧（#196795）

| 文件 | 改动点 | 分析 |
|------|--------|------|
| dp_parser.c | `panel_notifier_support = of_property_read_bool("qcom,panel-notifier-support")` | 通过 DT 属性开关，兼容旧平台（默认 false 不注册） |
| dp_panel.c | `drm_panel_init + drm_panel_add + sde_conn->panel 挂接` | 把 DP 面板注册为标准 drm_panel，使 sde_kms 能发 panel_event_notifier；`edp-drm-panel` 设备名 |
| dp_panel.c deinit | `drm_panel_remove + of_node_put + sde_conn->panel=NULL` | 对称清理，防悬垂指针 |
| dp_panel.h | `drm_panel / panel_dev / drm_panel_registered` 字段 | 状态跟踪 |

> 风险点：`drm_panel_add()` 在 A16 返回 void（A14 曾返回 int），代码注释已注明 A16 差异；若后续回移植到 A14 需处理返回值。

### 触摸侧（#196796）

| 文件 | 改动点 | 分析 |
|------|--------|------|
| sis_i2c.c | `sis_irq_suspended` 新增状态 | 修正原先 suspend 时手势模式/非手势模式 IRQ 管理混乱的问题 |
| sis_i2c.c | BLANK early trigger：手势模式→`enable_irq_wake`；否则→`disable_irq`+记录 | 手势模式保持唤醒中断，普通模式省电 |
| sis_i2c.c | UNBLANK：手势模式→`disable_irq_wake`；否则→`enable_irq` | 对称恢复 |
| sis_i2c.c | `gpio_is_valid()` 校验 en/rst GPIO | 防止非法 GPIO 号导致崩溃（DT 未配置时的健壮性） |
| egalax_i2c.c | `!cookie || IS_ERR(cookie)` | **关键修复**：`panel_event_notifier_register` 失败时返回 ERR_PTR，原实现只判 `!cookie` 会误判成功 |

## 潜在风险

1. **IRQ 管理对称性**：手势模式开启但系统深度 suspend（irq_wake 无效）时，唤醒可能失败；需功耗实测
2. **DRM panel 生命周期**：`edp-drm-panel` 与 connector 的绑定顺序（bind 流程中 sde_conn 可能未保证非 NULL）
3. **性能**：手势模式屏灭时触摸 IC 保持工作，功耗略增

## 回归测试建议

- 手势唤醒：双击/滑动息屏唤醒 × 100 次
- 普通息屏恢复（非手势模式）：触摸恢复正常
- 插拔 DP/eDP 显示器 + 息屏唤醒组合场景
- 长时间息屏（>8h）功耗对比

## 与现有驱动架构的关系

- 与 yupik 平台 DP 架构（sde_connector / dp_panel）紧密关联；
- 手势唤醒数据流与 A14 已有 sis95xx 手势逻辑一致，A16 仅修正 IRQ 与注册路径；
- 该平台目录为 Rigel 项目专用，与其它 yupik 平台（SM7325-A13）显示架构同源但版本不同。
