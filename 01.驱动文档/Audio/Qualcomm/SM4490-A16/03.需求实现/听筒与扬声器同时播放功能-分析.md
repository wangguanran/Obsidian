# 分析：听筒与扬声器同时播放功能

**版本号：v1.0**
**对应文档：** 听筒与扬声器同时播放功能.md

## 技术背景

Qualcomm Android 音频栈中，**audio HAL（audio-hal/primary-hal）** 位于 AudioPolicy/APM 与 PAL（Primitive Audio Library）之间：

```
AudioFlinger / AudioPolicyService (APM)
        │  AIDL
        ▼
audio-hal primary-hal  (AudioPrimaryHal / Platform)
        │  PAL API
        ▼
PAL → ADSP/APM (Audio Processing Manager) → MI2S/SWR 等 backend → Codec/PA → Speaker/Handset
```

`Platform::customizePalDevices()` 是 HAL 平台层在下发 PAL 设备列表前的**最后修改点**：APM 已经完成路由决策（选定输出设备），HAL 可以在这里对 `std::vector<pal_device>&` 做增删改。该函数在 parrot 平台的既有用途包括 HAC（助听器兼容）标记、HiFi PCM 滤波器配置等，本补丁在其末尾追加了媒体双通路逻辑，属于对同一钩子的复用。

两个关键 HAL 设备枚举：`PAL_DEVICE_OUT_SPEAKER`（外放喇叭）与 `PAL_DEVICE_OUT_HANDSET`（听筒/接收器），在 parrot 平台分别对应不同的 MI2S 后端通路，因此设备列表中同时存在两者时，PAL 会让同一路媒体流在两个后端上同时输出。

## 代码改动分析

### 1. configs/parrot/parrot.mk（+5）

在 `audio.deep_buffer.media=true` 之后新增：

```makefile
#Simultaneous audio output
PRODUCT_PROPERTY_OVERRIDES += \
persist.vendor.audio.media.spk_rcv_dual=false
```

- 定义了量产默认值 **false**（默认关闭），随 vendor 镜像固化；
- 使用 `persist.` 前缀使属性可持久化，运行期 `setprop` 生效；
- 位于 parrot 平台专属 configs 目录，不影响其他平台。

### 2. hal/core/platform/Platform.cpp（+52）

- **`kMediaSpkRcvDualProp`**：非 persist 形态的属性名（兼容冗余判断）；
- **`isMediaPlaybackUsecaseForSpkRcvDual()`**：白名单判断，覆盖 8 种媒体播放 usecase（PRIMARY / LOW_LATENCY / DEEP_BUFFER / ULL / MMAP / COMPRESS_OFFLOAD / PCM_OFFLOAD / SPATIAL），**刻意排除** VOIP、Telephony 等语音 usecase——语音通路叠加听筒+外放会产生啸叫/回声；
- **`maybeAppendHandsetForMediaSpkRcvDual()`**：
  1. 任一属性为 true 才继续；
  2. usecase 必须在白名单内；
  3. 设备列表必须**恰好只有 SPEAKER**（排除耳机、蓝牙、USB 等叠加场景）；
  4. 复制 SPEAKER 设备为 HANDSET（继承采样率/位宽等 config），清空 custom_key，`push_back` 追加；
  5. 打印 LOG(INFO) 便于验证。
- **`customizePalDevices()`** 末尾调用该函数，天然对所有输出通路生效。

## 潜在风险

1. **音量/功率**：听筒与扬声器同时满幅输出可能超出功放/听筒额定功率，存在硬件过载风险——需要结构/音频团队确认目标场景音量和增益；
2. **回声**：若设备上方音腔设计使听筒与扬声器声场耦合，大音量下可能产生互调/回声，需实测；
3. **属性残留**：`persist` 属性刷机不全会保留，量产如未在 mk 中固化可能沿用测试期 true 值；
4. **非 parrot 平台不受影响**：本改动严格限定在 parrot configs + Platform.cpp（同文件被其他 SM4490 平台共用时，属性默认 false 即无行为变化，风险低）。

## 回归测试建议

1. 属性关闭（默认）下回归：媒体播放、通话、录音主流程无变化；
2. 属性开启下验证：媒体播放（含 deep buffer、低延迟、offload、MMAP）双通路输出；插耳机/蓝牙时仅对应设备输出；接通电话/发起 VoIP 通话时无叠加输出；
3. 长时播放（1h+）老化测试，确认无过热、无失真、无听筒损伤；
4. 开关属性前后各重启一次，确认属性持久化与回退正常。

## 与现有驱动架构的关系

- 该功能**未改动** APM 路由策略与内核 audio 驱动，全部逻辑收敛在 HAL 平台层钩子内，符合"平台差异尽量留在 HAL 配置层"的设计原则；
- 与 [项目代号]（同 SM4490 parrot 平台的既有文档）的 RX macro 禁用改动互补：[项目代号] 侧重于裁剪未用通路降功耗，本改动在 [项目代号] 上复用 parrot 通路做双输出增强；
- 后续如需按使用场景（如仅外放增强、仅媒体应用白名单）进一步裁剪，可只修改 `maybeAppendHandsetForMediaSpkRcvDual()` 一处，扩展性好。
